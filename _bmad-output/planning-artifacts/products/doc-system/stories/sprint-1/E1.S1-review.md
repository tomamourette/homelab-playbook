## Adversarial / Cynical Review

### Hidden assumptions exposed

1. **"Claude Code resolves `@AGENTS.md` imports relative to the importer."** — *Safe.* The Anthropic memory doc (https://docs.claude.com/en/docs/claude-code/memory) verbatim describes the pattern: "create a `CLAUDE.md` that imports it so both tools read the same instructions without duplicating them." The `@path` syntax is a documented Claude Code memory primitive and resolves relative to the file containing the import. AC6 confirms in operator session.
2. **"The 11-byte stub `@AGENTS.md\n` (no leading text, no trailing content) is itself a valid import directive."** — *Fragile-but-likely-safe.* The Anthropic doc shows examples with surrounding prose, but does not forbid a bare-import file. If Claude Code's parser requires non-import content above/below the directive, the stub fails silently (file loads as zero rules, not as AGENTS.md). AC6 Probe 1 (file-organization rule check) is the only proof. This is the single most load-bearing untested assumption in the story.
3. **"OpenAI Codex, Cursor, and Continue read `AGENTS.md` natively without going through `CLAUDE.md`."** — *Open.* This is the whole point of the Astral pattern but is NOT verified by E1.S1. It is deferred to E1.S6 / E8.S1 / E8.S2. The user-story sentence "so that Claude Code, OpenAI Codex, Cursor, and Continue can all read the same canonical agent-instruction file" is therefore aspirational under E1.S1 alone — only the Claude Code arm gets exercised here.
4. **"No tooling in this repo references `CLAUDE.md` by literal filename."** — *Wrong, see gaps section.* `docs/source-tree-analysis.md`, `.claude/skills/bmad-quick-dev/workflow.md`, `.claude/skills/bmad-code-review/workflow.md`, `.claude/commands/monitoring/agents.md`, and the parallel `_bmad/bmm/4-implementation/*/workflow.md` copies all literally name `CLAUDE.md`. None will *break* (the file still exists as a stub), but several will load 11 bytes when they think they're loading rules. The BMAD workflow files in particular say "CLAUDE.md / memory files (load if exist)" — they load it, see `@AGENTS.md`, and unless the BMAD loader resolves `@`-imports the rules are silently empty for those workflows.
5. **"No pre-commit hook covers root-level `.md` files."** — *Verified.* Dev confirmed no hook fired and no `--no-verify` was needed. Repo has no husky/pre-commit infrastructure on this path.
6. **"The em dash in the commit subject survives all git clients and CI parsers."** — *Safe in practice.* UTF-8 commit subjects are standard since git 1.7+. Worth a glance only if a downstream tool (Jira sync, slack-notifier, GitHub Actions) does naive ASCII normalization, but no such tool exists in this repo today.
7. **"Auto-memory at `~/.claude/projects/-home-developer-workspace-homelab/` is unaffected by repo-root file rename."** — *Safe.* That directory is keyed by the workspace path, not by the filename `CLAUDE.md`. Confirmed populated and active (697KB session log dated 2026-04-28). The OMEGA `MEMORY.md` index also lives outside this repo.

### What could break this in 6 months

- **Anthropic deprecates or rewrites the `@import` syntax.** The doc URL is documentation-versioned (no API contract). If Claude Code v2 changes resolution semantics (e.g., requires `[[import:AGENTS.md]]` or makes imports opt-in via settings), the stub becomes a dead 11-byte file and rules silently disappear. Mitigation: pin the Anthropic doc URL + revision date in ADR-003 and re-verify on every Claude Code minor upgrade.
- **A future contributor edits the stub `CLAUDE.md` directly**, not knowing it's a redirect — adding a rule there will be loaded by Claude Code (per Anthropic doc, you can put Claude-specific instructions below the import) but invisible to Cursor/Codex. The story explicitly defers this case ("until a real divergence exists") — fine, but a single comment line at the top of the stub (`<!-- This file is a redirect. Edit AGENTS.md instead. See ADR-003. -->`) would prevent the foot-gun. Story 2 of the schema track should consider adding this guard line as part of the audit pass, after verifying it doesn't break the bare-import assumption (#2 above).
- **gitnexus or ruflo introduces a hard-coded `CLAUDE.md` reader** (e.g., a feature that ingests `CLAUDE.md` for project context). Today neither does for this repo, but ruflo's roadmap is unbounded. Mitigation: subscribe a CI grep for `CLAUDE.md` reads in any new ruflo/gitnexus minor release notes.
- **Drift accumulates in BMAD workflow files** (#4 in hidden assumptions). Each new BMAD skill copy-pastes "load CLAUDE.md if exists" boilerplate. Without a normalization sweep, the stub-load-vs-rule-load ambiguity grows. Recommend adding "AGENTS.md (preferred) / CLAUDE.md (fallback stub)" to the BMAD workflow boilerplate template in a follow-up.

### Edge cases not exercised

- **Symlinked CLAUDE.md or AGENTS.md.** Neither is a symlink today (`file` reports both as plain ASCII/UTF-8 text), but if a future contributor symlinks `CLAUDE.md → AGENTS.md` to "simplify" the redirect, Claude Code's `@`-import resolution against a symlinked importer is undefined by the doc. Probably fine, untested.
- **AGENTS.md absent at session start** (e.g., partial checkout, sparse checkout, broken submodule). The stub `@AGENTS.md` becomes a dangling import — Claude Code's behavior is undocumented. Probably loads zero rules silently.
- **Recursive `@`-imports.** Anthropic doc states a 5-level limit. The current AGENTS.md contains zero `@` imports, so this is moot today, but E1.S3 (topic split into `.claude/rules/<topic>.md`) will introduce them and must respect the limit.
- **Concurrent session reading mid-rename.** A Claude Code session running during the `mv` + `printf` window (~milliseconds) could in principle observe a transient state where `CLAUDE.md` is missing. Practical risk: zero — Claude Code does not poll memory files during a session.
- **Read-only filesystem on AGENTS.md.** Not a problem for read-only loaders; would block future `bmad-update-project-docs` writes. Untested, low risk.
- **Case-insensitive filesystem (macOS default, NTFS on Windows).** `claude.md` vs `CLAUDE.md` would collide. Linux ext4/zfs in this homelab is case-sensitive — no risk here, but worth noting if the pattern is exported to Windows/Mac dev machines.
