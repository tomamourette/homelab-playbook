# Story E1.S3: Pass 2 — topic split + content corrections

## User Story

As the homelab operator, I want to split AGENTS.md content into focused topic
files at `.claude/rules/<topic>.md` AND correct three residual issues from the
E1.S2 adversarial review (npm-vestigial Build & Test, JS/TS-inherited Project
Architecture bullets, dangling "swarm" terminology), so that the schema is
organized for PR review-ability and accurately describes the homelab's actual
nature (Terraform / Ansible / Docker / BMAD across three sub-repos) rather than
residual ruflo content.

## Context

E1.S1 redirected `CLAUDE.md` to a one-line `@AGENTS.md` stub (per Anthropic's
"AGENTS.md is the new home" guidance). E1.S2 cut AGENTS.md from 167 → 73 lines
by removing ruflo-specific blocks (model routing, swarm rules, CLI commands,
agents catalog, MCP setup, support links) and added a `## Pointers` tail
naming five `.claude/rules/<topic>.md` files. This story executes that split
and applies three content corrections that were promoted out of E1.S2's
Stage 4 review for non-trivial scope.

Architectural rule: per Anthropic's memory documentation
(<https://docs.claude.com/en/docs/claude-code/memory>), `@`-imports inside
`CLAUDE.md` / `AGENTS.md` are **eager**, not lazy — the imported file is read
at session start, the same as inlining its bytes. Therefore this topic split
**does not save session-start tokens by itself**. Its real benefits are:

1. PR review-ability — smaller files, focused diffs (a docs change doesn't
   touch security rules).
2. Topic isolation — clearer ownership, easier ADR cross-references.
3. Future genuine lazy-load — E1.S4 (next story) will add `paths:` frontmatter
   to the rules files so they are only injected on path-scoped edits. That is
   the actual session-start size win, not this story.

### 2. Correction (a) — Build & Test block (npm-vestigial)

The current `## Build & Test` block (lines 33-47) prescribes
`npm run build / test / lint`. There is **no `package.json`** at the homelab
workspace root. The homelab is Terraform / Ansible / Docker / BMAD across
three sub-repos:

- `homelab-infra/` — Terraform + Ansible (no npm)
- `homelab-apps/` — Docker Compose stacks (no npm)
- `homelab-playbook/` — BMAD methodology + Python tools (no npm)

**Fix (recommended):** scope out workspace-level Build & Test entirely. There
is no top-level build target; each sub-repo has its own conventions.
`.claude/rules/testing.md` keeps the two principle-level imperatives
("ALWAYS run tests after making code changes" / "ALWAYS verify build succeeds
before committing") and adds a one-line per-repo pointer:

```markdown
## Build & Test

No workspace-level build. Per sub-repo:

- `homelab-infra/`: `terraform fmt && terraform validate && ansible-lint`
- `homelab-apps/`: `docker-compose config` + per-stack lint as defined in stack README
- `homelab-playbook/`: BMAD validation flows (see `homelab-playbook/AGENTS.md`)

Always run the relevant sub-repo checks after code changes and verify they
pass before committing.
```

### 3. Correction (b) — Project Architecture bullets (JS/TS-inherited)

- Prefer TDD London School (mock-first) for new code

These are JS/TS-SaaS-product idioms inherited from ruflo, not homelab

```markdown
Homelab workspace: Proxmox VE 9 cluster + Terraform + Ansible + Docker.

```

**B. `.claude/rules/general.md` Project Architecture section (4-6 bullets,
operator-overridable at code-review):**

- Three-repo split: `homelab-infra` (Terraform + Ansible), `homelab-apps`
  (Docker Compose stacks), `homelab-playbook` (BMAD + runbooks). Cross-repo
  changes go in dependency order: infra → apps → playbook.
- Idempotent runbooks: every operation must be safe to re-run. No imperative
  one-shot scripts in `scripts/`.
- Tailscale-by-default for internal services (per existing operator policy);
  public DNS only when explicitly required.
- Single source of truth per fact-type (per ADR-002): one canonical location
  per concept, derived surfaces are one-way mirrors only (per ADR-010).
- Frontmatter on docs/wiki MD where ADR-005 applies (not yet enforced
  workspace-wide; called out for awareness).
- Keep individual files under ~500 lines for review-ability.
