# E1.S2 Adversarial Review — Audit cuts on AGENTS.md

## Verdict

PASS-with-followups. The cuts were executed cleanly and Stage 3's mechanical findings hold. But the file that survived is half-vestigial: it carries JS/TS-project assumptions (`npm run build/test/lint`, "TDD London School", "event sourcing") into a workspace whose three constituent repos are Terraform/Ansible/Docker/BMAD — not a single `package.json` exists at the workspace root. The cuts removed ruflo *labels*; they did not remove ruflo's *worldview*. None of this blocks the story (it was scoped subtractive-only), but several findings should be carried into E1.S3 as required scope, not optional polish.

## Cynical Findings

### Hidden assumptions exposed

1. **"`npm run build / npm test / npm run lint` are valid homelab commands."** FRAGILE. `ls /home/developer/workspace/homelab/package.json` returns no-such-file. None of the three repos under the workspace root (homelab-infra, homelab-apps, homelab-playbook) are JS projects — they're Terraform/Ansible, Docker Compose, and BMAD-docs respectively. AGENTS.md lines 33–47 instruct Claude to run commands that will fail with `npm: command not found` or `ENOENT package.json` on every invocation. Stage 3 noted the block was "byte-identical kept" — correct mechanically; wrong substantively. This is the single largest residual ruflo assumption that survived the cut.

2. **"Project Architecture bullets (DDD, files <500 lines, typed interfaces, TDD London, event sourcing, input validation) describe the homelab."** FRAGILE. These describe a JS/TS SaaS application, not a homelab. "Use event sourcing for state changes" — homelab uses Proxmox API + Terraform state + Ansible facts; nothing event-sourced. "Use typed interfaces for all public APIs" — Ansible playbooks have no typed interfaces. "Prefer TDD London School (mock-first) for new code" — the homelab has Molecule tests for Ansible roles and almost no JS/TS code. Stage 3 flagged this as a candidate for E1.S3 (suggested followup #3); the adversarial framing escalates: these aren't *aspirational* rules, they're misleading rules that contradict the actual repo's idiom.

3. **"73 lines is meaningfully under the 120-line target with no value left on the floor."** OPEN. The 73 lines include ~15 lines of Build & Test (npm) + ~6 architecture bullets that are actively misleading. If ~20 lines of that are vestigial, the actual *correct* surface area is ~53 lines — leaving 67 lines of headroom for genuine homelab content (Tailscale-default, 3-repo split, Proxmox conventions, secrets layout) that isn't there yet. The cap was met; the budget was not used wisely.

4. **"The Concurrency rule 'Use Claude Code's Task tool for spawning agents, not just MCP' makes sense post-ruflo-cut."** FRAGILE. Stage 3 already flagged this (suggested followup #1). The adversarial test: search for the *referent* of "MCP" elsewhere in the workspace. `.claude/skills/` still contains 80+ skill files, many of which (sparc-methodology, v3-*, swarm-*, hive-mind) reference `mcp__claude-flow__*` tools. The bullet "not just MCP" is therefore *still load-bearing* in the live skill ecosystem — the rule applies, but the reader of post-cut AGENTS.md has lost the context to understand it. This is residual coupling, not a dead reference.

5. **"The Concurrency rule 'spawn ALL agents in ONE message via Task tool' applies to subagent dispatches like the pipeline currently running."** FRAGILE. Director-mode pipelines (the one running this Stage 4 review) dispatch *sequentially per stage*, not all-in-one-message. The rule was correct for ruflo's parallel-swarm execution model; it's noisy/contradictory for staged-pipeline execution. AC verified the bullet is byte-identical — fine — but in actual practice this rule is selectively ignored by the pipeline that just verified it. Worth scoping in E1.S3 to "parallel work within a stage" rather than absolute.

6. **"The em-dash in the title H1 won't be normalized by any formatter or pre-commit hook."** SAFE — by absence. There is no `.prettierrc`, no `.markdownlint*`, no `.pre-commit-config.yaml` in the workspace root. The em-dash will survive because nothing is configured to touch it. This is safe today, but *only* because the workspace is unenforced, which is itself a finding (see #8 below).

7. **"The Pointers section accurately previews E1.S3's split."** FRAGILE — the 5 promised paths (`general.md`, `security.md`, `testing.md`, `docs.md`, `concurrency.md`) all live under `.claude/rules/`, but `.claude/rules/` does not exist. Until E1.S3 lands, every bullet in the Pointers section is a dangling link. If E1.S3 slips or partially ships, AGENTS.md will visibly broken-promise. Mitigation: this is exactly what the Pointers preamble ("Pass 2 (see E1.S3)") communicates; risk is bounded but real.

8. **"No frontmatter on AGENTS.md is correct per Anthropic."** SAFE. The Anthropic memory doc treats CLAUDE.md/AGENTS.md as plain markdown; head-1 is `# Homelab Workspace — Agent Instructions`. AC11 verified.

9. **"`Never continuously check status after spawning a swarm — wait for results` (Behavioral Rules line 10) still uses ruflo terminology."** FRAGILE. The word "swarm" is residual ruflo vocabulary — the surrounding `## Swarm Orchestration` section that defined it was cut, but the term survives in the kept Behavioral Rules block. Post-cut, "swarm" appears nowhere else in AGENTS.md, leaving this bullet as a vestigial pointer to a deleted concept. Stage 3 reviewed line-10 byte-identity but did not flag the dangling vocabulary. Correct phrasing post-cut: "Never continuously check status after spawning subagents — wait for results."

10. **"Single-revert reversibility means the cut state is the only state worth preserving."** SAFE-but-narrow. The revert restores 188 lines + 6515 bytes; AC10 verified. Subtler concern: any operator who *partially* edits AGENTS.md before E1.S3 will break the clean-revert contract, because the revert assumes pre-cut === a3475d3:AGENTS.md byte-for-byte. The window is small (E1.S2 → E1.S3) but unenforced.

### Inherited content the cuts missed

Walking the post-cut file line-by-line for residual ruflo worldview:

- **Lines 33–47 (Build & Test block).** The single largest miss. `npm run build`, `npm test`, `npm run lint` + the imperatives "ALWAYS run tests after making code changes" and "ALWAYS verify build succeeds before committing" — all assume a JS/TS project. The homelab's actual test commands are `molecule test` (Ansible), `terraform validate / plan`, `docker compose config`. The block should have been cut (no homelab context) or replaced (with the actual tools). Spec rationale was "INCLUDE row 'Bash commands Claude can't guess'" — but `npm run build` *is* guessable from `package.json`, and there is no `package.json`. This belongs in cut Pass 2 scope.

- **Lines 26–31 (Project Architecture bullets).** "Domain-Driven Design with bounded contexts", "files <500 lines", "typed interfaces", "TDD London School (mock-first)", "event sourcing", "input validation". Five of six are JS/TS-product idioms that don't map to homelab repos. Stage 3 suggested followup #3 flagged this softly; an adversarial reading says these bullets actively *misdirect* an agent reasoning about a Terraform module or Ansible role.

- **Line 10 (Behavioral Rules — "swarm" terminology).** See assumption #9 above. The word should be "subagents" or simply omitted post-cut.

- **Line 59 (`Use Claude Code's Task tool for spawning agents, not just MCP`).** The "not just MCP" is a polemical aside whose referent (ruflo's MCP swarm) is gone. Post-cut, the bullet reads as a non-sequitur. Stage 3 caught this.

- **Pointers section (lines 65–73).** Forward-pointing dangling links to `.claude/rules/*.md` files that don't exist yet. Acceptable as a per-spec deliverable; concerning if E1.S3 slips.

### What could break this in 6 months

1. **Bloat regression.** A future PR pastes ruflo content (or new BMAD content, or a 50-line ADR-summary) back in. No CI lint enforces ≤120, no pre-commit hook checks for `npx @claude-flow`. Stage 3 suggested followup #5 covers this; adversarial likelihood: high within 90 days given how organically these files grow.

2. **Anthropic deprecates `@`-imports or changes file precedence.** The stub `CLAUDE.md` containing `@AGENTS.md\n` depends on Anthropic continuing to honor that import syntax. If Claude Code makes `AGENTS.md` natively-loaded (it's already preferred per Anthropic memory doc), the stub becomes redundant; if Anthropic deprecates `@`-imports without a replacement, both files break. Mitigated only by E1.S6 cross-tool monitoring.

3. **Operator forgets the stub redirect.** Three months from now, Tom opens CLAUDE.md, sees `@AGENTS.md\n`, doesn't remember the indirection, and either deletes it or pastes in new rules. The 11-byte stub has zero discoverability — there's no comment line saying "this is intentional, see ADR-003". Cheap fix: add a one-line comment to CLAUDE.md.

4. **Pointers tail orphans.** If E1.S3 ships only 3 of the 5 promised topic files, the Pointers section becomes 60% broken links. Worse: if E1.S3 ships *different* filenames than promised, the bullets point at nothing.

5. **`npm` Build & Test block surfaces in a fresh session.** A new operator (or Claude itself in a context-fresh session) reads AGENTS.md, sees `npm run build`, runs it, gets an error, loses trust in the rules file. Likelihood: medium — this is exactly what unfamiliar agents do.

6. **A future BMAD skill auto-validates AGENTS.md against a schema.** `bmad-document-project` or `bmad-validate-prd` may grow a "must mention 3-repo structure" or "must reference Tailscale" check; the post-cut file would fail. Speculative but plausible given BMAD's trajectory.

### Edge cases not exercised

1. **Recursive `@`-imports.** E1.S3 may introduce `@.claude/rules/general.md` syntax. Anthropic's memory doc allows nested imports up to depth 5 — but the homelab hasn't tested any nesting yet. The stub→AGENTS chain is depth-1; Pass 2 may push to depth-2 and beyond.

2. **Line endings.** AGENTS.md is LF (verified `file` returns "Unicode text, UTF-8 text" with no CRLF flag). If a Windows contributor opens it in an editor that auto-converts to CRLF and re-commits, all 73 lines will diff. No `.gitattributes` enforces LF.

3. **Trailing newline pedantry.** `od -c` confirms exactly one terminating newline (file ends `\n`). Stage 3 noted this is "harmless either way"; adversarial check confirms — but no `.editorconfig` enforces it, so future edits could regress to no-trailing-newline or double-trailing-newline silently.

4. **Em-dash on terminals/CIs without UTF-8 locale.** The H1 uses U+2014. A CI runner or grep with `LANG=C` would treat it as bytes `e2 80 94`, not a single character. AC verification used `od -c` which is correct; future regex-based AGENTS.md lints may need to be UTF-8-aware.

5. **Model-variant differences.** This Stage 4 review runs on Opus 4.7 1M. If a future operator session uses Haiku 4.5 (cheaper, smaller context), does the 73-line file still parse coherently? Probably yes, but untested. The "behavioral check" referenced in spec Step 6 should be done at least once on each model tier.

6. **Frontmatter race.** AC11 confirms no frontmatter today. If a future tool (e.g., a docs-indexer) auto-prepends YAML frontmatter to all `*.md` files, AGENTS.md becomes a YAML+markdown hybrid that the @-import mechanism may or may not handle gracefully. No protection exists.

7. **Larger-than-200-line regression alarm.** If a future edit makes AGENTS.md 200+ lines, nothing alarms. The 120-line target is a documented soft cap with no enforcement.

2. **Rephrase Behavioral Rules line 10 to drop "swarm" vocabulary.** Replace `Never continuously check status after spawning a swarm — wait for results` with `Never continuously check status after spawning subagents — wait for results`. Captures the same rule without residual ruflo vocabulary.

3. **Encode AC3+AC4 grep probes as a CI lint.** Stage 3 raised this; adversarial framing seconds it strongly. The 13 cut-greps + 7 keep-greps + a `wc -l ≤ 120` check + a `grep -c 'npx @claude-flow' AGENTS.md == 0` check, run as a `homelab-playbook` CI job, would give the file a regression guard.

4. **Add a `.gitattributes` entry pinning `*.md` to LF line endings.** One-line file change; protects against Windows-contributor CRLF drift.

5. **Schedule an E1.S6 reference-graph scan.** Before cross-tool validation, scan all skill files / runbooks / docs for string references to deleted AGENTS.md section names. Confirms whether the cuts orphaned anything beyond AGENTS.md itself.

6. **Plan an E1.S3-or-later "add homelab-native content" story.** The cuts removed noise; nothing yet adds signal. A short story to introduce 3-repo split awareness, Tailscale-default policy, secrets-via-vault note, and Proxmox cluster context would close the gap between "ruflo content removed" and "homelab content present".
