# Story E1.S2: Audit cuts on AGENTS.md (≤120 lines target)

## User Story

As the homelab operator, I want to cut ruflo/V3 product reference content from `/home/developer/workspace/homelab/AGENTS.md` and reduce its line count from 189 to ≤120, so that Claude Code's session-start context budget stays lean (per Anthropic's verbatim guidance "target under 200 lines per CLAUDE.md file") and the file contains only project-specific rules — not third-party tool reference content that bloats every session and degrades adherence.

## Context

The current `AGENTS.md` (189 lines / 6515 bytes, post-E1.S1 commit `a3475d3`) is a checked-in copy of the ruflo/claude-flow V3 starter template. Roughly 60% of it is ruflo product reference: CLI tables, agent catalogs, swarm orchestration lectures, MCP setup commands, support links. Only ~40% is genuine project rule content (behavioral rules, file organization, build/test, security, concurrency, project-architecture conventions).

The homelab is currently trending toward the documented anti-pattern: a 1,094-line ruflo reference `CLAUDE.md` (schema research §4 anti-patterns). Anthropic explicitly warns against this:

> "Keep it concise. For each line, ask: 'Would removing this cause Claude to make mistakes?' If not, cut it. **Bloated CLAUDE.md files cause Claude to ignore your actual instructions!**" — https://code.claude.com/docs/en/best-practices

This story performs the first round of audit cuts (Pass 1). E1.S3 (Pass 2) will then split the kept content into topic-scoped `.claude/rules/<topic>.md` files; this story is only about subtractive cuts plus the title H1 change and a small Pointers tail.

## Anthropic-Endorsed Cut Criteria

### Verbatim size guidance

> "**Size**: target under 200 lines per CLAUDE.md file. Longer files consume more context and reduce adherence." — https://code.claude.com/docs/en/memory

We target ≤120 lines (40% headroom under Anthropic's 200-line ceiling, per architecture §11).

### Verbatim bloat warning

> "Keep it concise. For each line, ask: 'Would removing this cause Claude to make mistakes?' If not, cut it. **Bloated CLAUDE.md files cause Claude to ignore your actual instructions!**" — https://code.claude.com/docs/en/best-practices

### Verbatim include/exclude table

From schema research §2.1 (Anthropic best-practices doc):

| INCLUDE in CLAUDE.md / AGENTS.md | EXCLUDE (use other mechanisms) |
|----------------------------------|--------------------------------|
| Bash commands Claude can't guess | Detailed API documentation (link to docs instead) |
| Code style guidelines specific to your project | Anything Claude can figure out by reading code |
| Testing instructions and conventions | Information that changes frequently |
| Repository etiquette and PR rules | Generic best practices |
| Developer environment setup quirks | Long lists Claude can hallucinate |
| Project-specific warnings or gotchas | Tool reference for third-party tools |

Every cut below maps to one or more EXCLUDE rows.
