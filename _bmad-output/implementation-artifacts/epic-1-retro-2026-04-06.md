## Challenges and Growth Areas

### Pattern 1: Implicit Cross-Repo Conventions (Story 1.1)

Story 1.1 used `ansible_env.HOME` — the standard Ansible pattern — but didn't account for `become: true` resolving HOME to `/root`. The dev-host role uses `become: true` but this convention wasn't surfaced in the story's Dev Notes.

**Root cause:** Cross-repo conventions (how dev-host executes) weren't explicitly documented in story context. The assumption was implicit.

**Impact:** 3 patches in Story 1.1 (P1, P2, P3). Self-corrected in subsequent stories via progressive learning.

### Pattern 2: No Epic-Level Prerequisite Verification

Epic 0's workflow improvements were adopted in Epic 1, but by luck, not by design. There was no formal verification step that confirmed the workflow was ready for the new Ansible domain.

**Root cause:** Story-level Task 0 exists, but no equivalent epic-level gate.

### Pattern 3: No End-to-End User Journey Tests

12 component-level VERIFY checks existed, but no integration test from the user's perspective ("can I SSH in, see the TUI, survive a disconnect, survive a reboot").

**Root cause:** Validation criteria defined at the story level (technical checks) but not at the epic level (user journey).

### Pattern 4: Untracked Workspace Files

`.claude/skills/` (77 skill directories including all Epic 0 wrappers) lives at the workspace root, which is not a git repo. These files are not version-controlled, not backed up, and not reproducible on a new container.

**Root cause:** The workspace root (`homelab/`) contains three sub-repos but isn't itself a git repo. Skills installed at the workspace level fall outside all version control.

### Pattern 5: No Separate Test Container

Development and deployment happen on the same container (`ct-dev-homelab`). A role that breaks something (e.g., clobbers `.bashrc` or Claude Code settings) could break the active development session.

**Root cause:** No clean-room verification target exists.

## Key Insights and Learnings

1. **Story-level Task 0 works — extend to epic-level gates.** Entry Gate at sprint planning (verify prerequisites, define validation criteria, reserve user journey tests). Exit Gate at retrospective (run validations, present results as interactive checklist).

2. **Define validation criteria at sprint start, verify at sprint end.** User journey tests bridge the gap between technical VERIFY checks and stakeholder-visible outcomes. Define them upfront so the dev agent knows the endgame.

3. **Test-then-deploy per story on a separate container.** Write on `ct-dev-homelab`, deploy to `ct-dev-test`, verify there, then apply to `ct-dev-homelab`. Protects the working environment from breaking changes.

4. **Workspace-level files must be version-controlled.** Git init at workspace root, gitignore the three sub-repos. Skills, settings, BMAD config, and docs become tracked and reproducible.

5. **Python 3.11+ is not installed by dev-host.** pyenv is installed but no Python version is configured. Must add `pyenv install 3.11.x` + `pyenv global 3.11.x` to dev-host before Epic 2.
